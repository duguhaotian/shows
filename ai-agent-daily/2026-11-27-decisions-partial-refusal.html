Decisions API：分流答对了，证据也可能没答

文章元信息

OpenAI，2026-10-22，Build more responsive apps with the Decisions API。体裁：产品发布与工程指南，不是独立基准报告。标签：结构化决策、逐题拒答、路由验收。

一句话结论：一次请求可以同时回答了分流、拒答了证据判断；程序应逐题验收，缺少必要证据就不推进发布。

核心技术点 / 核心思路

  • 把判断写成有边界的问题。调用方给出材料、问题和预设答案。predicate 给条件为真的概率，choice 从预设选项中选，score 按预设等级评分。它们适合消费结构化结果，但不替调用方决定权限或提供独立证据。
  • 只合并互不依赖的问题。对同一段材料，「来源属于哪一类」和「给定引文是否支持指定主张」可以独立提问；若后题的标准取决于先判出的类别，则先判类别，再生成相应问题并单独发起请求。指南：多问题。
  • 答案、拒答、缺失分别处理。参考文档允许同一响应里有正常答案和逐题 refusal，并给出问题名称（未命名时可为 null）。用唯一名称、预期类型和允许值校验每个必需结果。显式「不确定」是有效回答；拒答是模型不答；预期项缺失或类型不符是调用方要定位的异常。三者都不能当成「证据通过」。返回类型。

流程图：把分流与验收拆开

原文要点

OpenAI 在发布文中报告，相比通过 Responses API 调用 GPT‑6 Luna，Decisions 的有界判断最快可达 10 倍速度。这是供应商给出的特定比较，不是与 Jev 的对比，也不是 Agent 完成任务的速度。指南建议从一个高频判断开始，先用代表性样本检验问题、选项和上下文设计。

实践建议

我的建议：先用规则做精确去重、必填栏目和目录检查。若日志显示「来源初筛」成为瓶颈，再做一次影子评测：模型给建议但不改变结果，更不操作发布。人工提前标注样本，按来源或题材隔离开发集与留出集，覆盖中英混合、证据缺失和多个选项都似乎合理的情况。

用于检验流程的合成用例，非 API 实测
可观察结果建议处理
分流有效，证据题拒答保留分流建议，补查原始证据，不发布。
证据题返回明确「不确定」进入证据复核，记录与拒答不同的原因。
缺少约定的证据项或类型不符记录接口异常，不默认成通过；按预算诊断。
两题均返回有效的正向判断继续核对原文及目标产物，按既有授权流程执行。

对比规则、现有模型与结构化模型时，按同一批输入统计错误放行率、进入复核的比例、端到端延迟和每个验收通过结果的总成本。把人工复核、升级与重试纳入成本，不用孤立的每次调用价格选型。

适用边界

选项少、标准稳定、错路由可回退时最适合试。复杂论证、需要外部核实的事实、权限和不可逆操作不能靠模型置信度放行。单次请求可合并多题不代表所有任务都该打成大包；问题有依赖时分开，并按实测预算判断。本文无真实 API 调用、成本或延迟测量。

后续跟进
