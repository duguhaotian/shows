Agent 评估：核验结果，而不只相信完成声明

来源：Anthropic · 发布于 2026-01-09 · 模板 v1.0

原文：Demystifying evals for AI agents

一句话结论：Agent 评估应核验真实结果，而不是只相信它说“完成了”。

原文要点

  • 把任务、重复试验、运行轨迹和最终状态分开看，避免把过程描述当成结果证据。
  • 能用代码验证的结果优先自动检查；使用模型评分时，需要人工判断来校准。
  • 能力测试用于寻找提升空间，回归测试用于保护已有能力。
  • 从真实失败中选取 20–50 个任务起步，隔离测试环境，并复查失败轨迹。
  • “多次试验中至少成功一次”和“每次都成功”衡量的是不同能力，不能混用。

实践建议：用于每日归档流程

以下为本次精读的延伸建议，并非作者针对本项目的结论。

  1. 内容检查：核对结论与来源，明确标注推断，不把尚未验证的建议写成事实。
  2. 结果检查：提交后重新读取 HTML，确认正文、日期、来源链接存在；核对索引指向当天文件。
  3. 交付检查：消息中的仓库链接应指向已存在的文件，不能仅凭写入请求成功就宣布归档完成。
  4. 失败测试：分别覆盖重复日期、仓库写入失败、原文不可访问；失败时保留已有文章并报告实际状态。

适用边界

适合需要重复执行、调用工具并产生外部结果的 Agent。小样本不能证明细微改进；离线评估仍需结合真实使用反馈。本文的归档检查建议尚不是已完成的实验，也不代表任何成功率承诺。

后续跟进

待验证：重复执行同一天的任务时，能否正确复用已归档结果，而不生成重复文章或覆盖原文？后续精读可继续补充评估指标与失败案例。
